## Definition of done

- Every screen renders on `NEXT_PUBLIC_USE_MOCKS=true` and on the memory backend with no code change.
- All test ids in `/app/CLAUDE.md` exist and `NEXT_PUBLIC_USE_MOCKS=true npm run test:e2e` passes for both projects.
- No hex colors, no `fetch` outside `/lib/api.ts`. English only UI (D-009).
- `npm run typecheck && npm run lint` clean.
- Agent Room looks alive: bubbles stream in, objection shakes, concession pulses, `plan-ready` appears after the decision.

## How to run and test

```
npm run setup            # once
# set NEXT_PUBLIC_USE_MOCKS=true in .env.local while screens are being built
npm run dev              # http://localhost:3000/welcome
npm run test:e2e -- --project=laptop
npx playwright screenshot --viewport-size=390,844 http://localhost:3000/plan plan-390.png
```

Switch the demo user in mock mode with the Profile `demo-user-switch` (sets localStorage `np_mock_user`), or `localStorage.setItem("np_mock_user","maria")` in devtools.

## Never touch

`/types/contracts.ts`, `/app/api/**`, `/agents`, `/math`, `/lib/db`, `/lib/auth`, `/supabase`, `scripts/generate-mocks.ts`. If a mock is wrong, ask the Lead to fix the generator rather than hand editing (hand edits are overwritten by `npm run mocks`).

## Requesting a contract change

Post in the group chat: "Contract request: <type>.<field>: <type> because <screen needs it>". The Lead edits `/types/contracts.ts`, regenerates mocks and schemas, and replies with the commit. Until then, derive what you need from existing fields in the hook, never in the component.
